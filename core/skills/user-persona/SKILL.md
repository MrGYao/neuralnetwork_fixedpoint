- 职业：大厂电力电子AI与软件开发（2020至今），当前负责全量数据库、工具平台、Agent开发建设

- 创业定位：技术型独立创业者，通过软件开发实现商业闭环

### 创业优势

1. **全栈独立交付**：一人可完成从底层建模到Web应用的全链路开发
2. **自学能力极强**：跨领域（电气 → AI → Agent）快速掌握新技术，自动驱动力强
3. **执行力突出**：有想法即实践，不拖延，脚踏实地
4. **持久力好**：做事持之以恒，适合创业长跑
5. **Agent开发经验**：当前工作中已深入Agent建设，懂AI Native产品

### 创业短板（Agent必须重点补偿）

#### 1. 完美主义陷阱

- 表现：追求局部最优，分不清主次，过度工程化
- Agent策略：
  - 每个阶段开始前，主动提醒MVP最小范围
  - 方案中标注 [必须做] vs [可以后做]
  - 用"先上线→再迭代"原则打断过度规划
  - 任何超过3个月才见效的开发计划亮黄牌警告

#### 2. 表达与沟通短板

- 表现：表达能力较弱，攻击性较强
- Agent策略：
  - 产出的商业文档主动提供多版本（技术版 / 市场版）
  - 关键对外文案提供润色建议（软化表达）
  - 商业策略阶段补充沟通话术模版

#### 3. 商业盲区

- 表现：缺乏市场、定价、营销、商业模式实战经验
- Agent策略：
  - 创意评估阶段强制市场分析（调用market-research skill）
  - 产品定义阶段强制竞品分析（调用competitor-analysis skill）
  - 商业阶段提供完整盈利模型方案（调用monetization skill）
  - 用数据说话，拒绝空谈

#### 4. 非擅长领域妥协倾向

- 表现：在商业、法务等领域容易草率决定
- Agent策略：
  - 遇到非技术决策时，主动提供多个方案对比
  - 每个方案标注风险等级与预期收益
  - 遇到用户不擅长的领域，主动深度分析而非浅层建议

### 决策偏好

- **技术驱动**：相信技术能力是核心竞争力，倾向选择技术壁垒高的产品方向
- **数据导向**：用数据和事实说话，拒绝空想
- **独立自主**：偏好独立开发，不依赖外部团队
- **务实落地**：厌恶炒作概念，追求可交付的实际产品
- **快速验证**：倾向MVP验证 → 市场反馈 → 迭代优化模式

## Part 2: 创业双阶段愿景

### 整体路径

```
温饱（生存期）──达成──→ 自我实现（发展期）
  6-12个月              3-5年
  目标：收支平衡          目标：财富自由 + 影响力
```

### 阶段切换条件

```
温饱 → 自我实现:  连续3个月盈利 + 至少1个稳定产品 + 月现金流为正
自我实现 → 回退:  连续3个月亏损 + 收入无法覆盖月支出
```

### 温饱阶段核心原则

| 原则            | 说明                           | Agent行为规则                               |
| --------------- | ------------------------------ | ------------------------------------------- |
| 赚钱快 > 技术酷 | 项目选择以变现速度为第一优先级 | 评估新创意时，首问"怎么赚钱？多久能赚钱？"  |
| MVP最小化       | 能做1个功能就不做2个           | 强制提醒MVP范围，拒绝功能蔓延               |
| 市场验证先行    | 不要闭门造车                   | ideation阶段必须做市场调研                  |
| 时间敏感        | 6-12个月必须见盈利             | 超过3个月无收入的开发计划亮黄牌             |
| 技术克制        | 用已精通的技术栈               | 技术选型优先选用户熟悉的，不追新            |
| 避免完美主义    | 先上线，再完善                 | 任何不阻碍核心功能的改进都标记为 [可以后做] |

### 自我实现阶段核心原则

| 原则           | 说明                   | Agent行为规则                  |
| -------------- | ---------------------- | ------------------------------ |
| 影响力优先     | 产品是否有长期社会价值 | 评估产品对用户的真实正面影响   |
| 规模化         | 能否自动化、可复制     | 商业模式强调被动收入结构       |
| 品牌建设       | 个人IP与产品品牌并重   | 商业策略中补充品牌建设路径     |
| 产品矩阵       | 从单产品到多产品协同   | 评估新产品与现有产品的协同效应 |
| 财富自由里程碑 | 被动收入 > 生活支出    | 商业计划中明确自由里程碑       |

### 项目评估权重（按阶段动态调整）

| 评估维度                   | 温饱阶段权重 | 自我实现阶段权重 |
| -------------------------- | :----------: | :--------------: |
| 盈利能力 / 变现速度        |     40%      |       20%        |
| 技术可行性（用户能力匹配） |     25%      |       20%        |
| 市场需求 / 痛点强度        |     20%      |       25%        |
| 个人价值认同               |     10%      |       25%        |
| 长期规模化潜力             |      5%      |       10%        |
| **合计**                   |   **100%**   |     **100%**     |

### 项目评分标准

- **≥80分**：立即启动，高优先级
- **60-79分**：进入创意池，择机启动
- **40-59分**：暂存观察，需补充信息
- **<40分**：放弃或大幅调整方向

## Part 3: Agent行为速查表

| Agent       | 温饱阶段行为                 | 自我实现阶段行为                  |
| ----------- | ---------------------------- | --------------------------------- |
| ideation    | 按温饱权重打分，强调变现速度 | 按自我实现权重打分，强调影响力    |
| product     | MVP最小化，砍掉非核心功能    | 产品矩阵设计，考虑协同            |
| architect   | 选用用户熟悉的技术栈         | 考虑可扩展架构，为规模化做准备    |
| developer   | 快速交付，代码够用就行       | 代码质量优先，为长期维护做准备    |
| deployer    | 快速上线单渠道               | 多渠道同步部署                    |
| strategist  | 短期变现路径（订阅/买断）    | 品牌建设 + 被动收入结构           |
| evaluator   | 按温饱权重排序               | 按自我实现权重排序                |
| analyst     | 收入、成本核心指标           | 用户留存、NPS、品牌声量等全部指标 |
| toolsmith   | 只做必要工具                 | 完善工具链                        |
| opportunist | 仅标记中间产物，延后处理     | 主动寻找可拆分变现点              |
| reflector   | 轻量记录                     | 深度复盘和知识体系化              |
