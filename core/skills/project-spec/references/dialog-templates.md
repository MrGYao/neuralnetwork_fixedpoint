# 引导式对话模板

本文档提供新建项目时的对话问题模板。在步骤 2 信息采集中，当进入"描述模式"时加载此文档。

---

## 新项目 - 基础问题

```
Q1: 项目核心目标
    "这个项目的核心目标是什么？打算解决什么问题？"

    追问（如回答模糊）：
    - "目标用户是谁？"
    - "成功的关键指标是什么？"

Q2: 技术栈偏好
    "计划使用什么技术栈？有什么偏好或约束吗？"

    追问：
    - 前端技术偏好？
    - 后端技术偏好？
    - 数据库选型？
    - 部署平台？

Q3: 核心功能
    "项目的主要功能模块有哪些？最核心的场景是什么？"

    追问：
    - "这些功能的优先级？"
    - "关键的用户流程？"

Q4: 架构偏好（可选）
    "有架构上的偏好吗？比如 Monorepo、微服务、前后端分离？"

    追问：
    - "为什么这样选择？"
    - "有必须遵守的约束吗？"

Q5: 演进规划（可选）
    "项目的短期目标和长期愿景是什么？"

    追问：
    - "第一版要达到什么程度？"
    - "未来可能扩展的方向？"
```

## 项目类型特定问题

### CLI 工具

```
Q_CLI_1: 命令设计
    "CLI 工具的主要命令有哪些？命名偏好？"
    示例："mytool scan <path> --format json"

Q_CLI_2: 输出格式
    "默认输出格式？支持哪些格式？"
    选项：JSON / YAML / 表格 / 纯文本

Q_CLI_3: 配置方式
    "如何配置？"
    选项：命令行参数 / 配置文件 / 环境变量
```

### Web 应用

```
Q_WEB_1: API 风格
    "API 设计风格？"
    选项：RESTful / GraphQL / gRPC

Q_WEB_2: 认证方式
    "用户认证方案？"
    选项：JWT / Session / OAuth / 无认证

Q_WEB_3: 部署环境
    "部署环境？"
    选项：云服务（AWS/GCP/Azure） / 自建服务器 / Docker / Kubernetes
```

### 桌面应用

```
Q_DESKTOP_1: 后端托管
    "是否托管后端服务？"
    示例：Electron 托管 FastAPI / 纯前端

Q_DESKTOP_2: 平台支持
    "目标平台？"
    选项：Windows / macOS / Linux / 全平台

Q_DESKTOP_3: 更新机制
    "如何处理应用更新？"
    选项：自动更新 / 手动更新 / 应用商店
```

```
检测到已有 spec/ 目录，当前内容：
  ✅ product/ - 完整
  ⚠️ solution/ - 缺少 DEPLOYMENT.md
  ❌ architecture/ - 未创建

你希望：
  1. 补充缺失部分（自动）
  2. 重新生成某个层级（指定）
  3. 新增特定文档（描述）
```

## 对话技巧

### 如何判断用户回答质量

**模糊回答**：

- "做一个好用的工具" → 追问具体场景和目标用户
- "用现代技术栈" → 追问具体框架偏好

**具体回答**：

- "用 React + FastAPI 做用户管理系统" → 可直接进入下一问题

### 如何引导用户深入思考

避免问"还需要什么吗？"（容易得到"没了"的浅层回答）

改问：

- "假设第一版上线后，用户反馈最多的问题可能是？"
- "有没有必须避免的技术或方案？"
- "性能要求是什么？预计用户量级？"

### 如何记录对话结果

```
对话摘要：
  - 项目类型：CLI 工具
  - 核心目标：代码复杂度分析
  - 技术栈：Python + click + radon
  - 核心功能：扫描目录、计算圈复杂度、输出报告
  - 架构：单文件 CLI
  - 演进：第一版 Python，未来支持 JS/Go

→ 用于生成 product/OVERVIEW.md 和 solution/TECH_STACK.md
```
