agent: build

模板文件位置：`.opencode/commands/auto-task/`

## 目的

任务最后阶段完成时，全面检查：

1. 各阶段summary文件是否存在
2. 各阶段产出与相应plan是否一致
3. 任务整体效果与预期是否一致
4. overall-plan退出条件是否全部达成

不一致则改进完成或标记遗留问题。

## 执行流程

### 1. 读取任务信息

a) 读取 memory-index.md，获取当前任务：

- 当前任务：task-{id}

b) 读取任务目录：

- auto-task/tasks/task-{id}/

c) 统计阶段信息：

- 阶段计划文件列表：task-{id}-plan-phase-*.md
- 阶段总结文件列表：summary/task-{id}-plan-phase-*-summary.md
- 阶段数量 = 计划文件数量

d) 读取 overall-plan 文件：

- task-{id}-analysis-overall-plan.md
- 提取退出条件列表

### 2. 检查各阶段summary

对于每个阶段（phase 1 ~ N）：

a) 检查 summary 文件是否存在：

- summary/task-{id}-plan-phase-{n}-summary.md

b) 如果存在：

- 读取内容，提取产出物列表
- 输出：✅ Phase {n} summary 存在

c) 如果不存在：

- 输出：❌ Phase {n} summary 缺失
- 记录到补充列表

### 3. 检查各阶段产出与plan一致性

对于每个阶段（phase 1 ~ N）：

a) 读取计划文件：

- task-{id}-plan-phase-{n}.md
- 提取产出物列表、验证标准列表

b) 读取总结文件（如存在）：

- summary/task-{id}-plan-phase-{n}-summary.md
- 提取实际产出物列表、验证结果

c) 对比分析：

- 计划产出 vs 实际产出
- 计划标准 vs 实际验证结果

d) 如果一致：

- 输出：✅ Phase {n} 产出与plan一致

e) 如果不一致：

- 输出：❌ Phase {n} 产出与plan不一致
- 列出差异项：
  - 缺失产出：{文件列表}
  - 未满足标准：{标准列表}
- 记录到修复列表

### 4. 检查任务整体效果

a) 读取 overall-plan 文件，提取：

- 任务目标
- 预期效果描述
- 成功标准

b) 评估实际效果（基于各阶段产出）：

- 所有阶段是否完成
- 主要产出物是否生成
- 核心功能是否实现

c) 对比预期效果与实际效果：

- 如果符合预期 → 输出：✅ 任务效果符合预期
- 如果部分符合 → 输出：⚠️ 任务效果部分符合预期
- 如果不符预期 → 输出：❌ 任务效果不符预期

d) 列出效果差异：

- 缺失功能：{列表}
- 性能问题：{列表}
- 其他问题：{列表}

### 5. 检查overall-plan退出条件

a) 读取 overall-plan 退出条件列表

b) 对于每个退出条件：

- 检查条件是否达成（基于实际产出）
- 如果达成 → 输出：✅ {条件描述}
- 如果未达成 → 输出：❌ {条件描述}

c) 统计达成情况：

- 达成数量 / 总数量

### 6. 输出检查报告

```
========================================
任务完成检查报告
========================================
任务：{task-id}
阶段数：{N}

阶段summary检查：
- ✅ Phase 1 summary 存在
- ❌ Phase 2 summary 缺失
- ✅ Phase 3 summary 存在

阶段产出一致性检查：
- ✅ Phase 1 产出与plan一致
- ❌ Phase 2 产出与plan不一致
  - 缺失产出：{文件}
  - 未满足标准：{标准}
- ✅ Phase 3 产出与plan一致

任务效果检查：
- ✅ 任务效果符合预期

退出条件检查：
- ✅ 条件1
- ✅ 条件2
- ❌ 条件3

总体状态：
- 达成条件：2/3
- 遗留问题：{数量}

========================================
```

### 7. 处理不一致情况

如果存在任何 ❌ 或 ⚠️：

a) 输出不一致项列表

b) 询问用户处理方式：

- "改进" → 执行改进逻辑
- "补充" → 执行补充逻辑
- "跳过" → 记录遗留问题
- "查看" → 输出详细信息后重新询问

c) 改进逻辑：

- summary缺失 → 调用 /at-plan-run 重新生成
- 产出不一致 → 对指定阶段重新执行或补充
- 效果不符预期 → 执行改进措施

d) 补充逻辑：

- 缺失产出 → 执行补充操作
- 未达成条件 → 完善实现或标记风险

e) 记录处理结果到任务完成总结

### 8. 更新overall-plan和完成任务

a) 更新 overall-plan 文件：

- 更新退出条件状态
- 记录检查结果
- 标记遗留问题（如有）

b) 更新任务完成总结：

- 添加检查报告内容
- 记录改进/补充操作

c) 提交变更：

- git add auto-task/tasks/task-{id}/
- git commit -m "[task-{id}] 任务完成检查：改进/补充产出"

### 9. 输出最终结果

```
========================================
任务完成检查完成
========================================
任务：{task-id}
状态：{全部一致 / 已改进补充 / 存在遗留问题}

处理结果：
- 补充summary：{数量}
- 改进产出：{数量}
- 遗留问题：{数量}

下一步：执行 /at-task-finish 完成任务
========================================
```

## 调用位置

在 `/at-task-run` 任务循环的 v) 阶段检查部分：

```
v) 检查是否存在下一阶段：

如果不存在（已到达最后阶段）：
- 输出"所有阶段已完成"
- **执行 /at-task-review**  ← 新增
- 退出阶段循环
```

**注意**：在 `/at-task-finish` 之前调用，确保任务质量后再标记完成。

## 关键原则

1. 全面检查：覆盖所有阶段、所有产出、所有条件
2. 纵向对比：阶段产出与计划一致性
3. 横向评估：任务整体效果与预期
4. 用户决策：不一致时询问处理方式
5. 记录完整：所有检查和处理记录到任务总结

## 错误处理

- overall-plan文件不存在 → 提示错误，退出
- 无法读取阶段文件 → 跳过该阶段，继续其他阶段
- 改进/补充失败 → 记录到遗留问题，不阻塞任务完成
