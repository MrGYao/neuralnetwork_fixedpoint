模板文件位置：`.opencode/commands/auto-task/`

## 目的

阶段计划执行完后，检查：

1. 产出物：计划中列出的产出文件是否全部存在
2. 验证标准：每个标准是否满足
3. 退出条件：每个条件是否达成
4. 内容一致性：产出文件内容是否符合预期

不一致则补充、修复或说明原因。

## 执行流程

### 1. 读取当前阶段计划文件

a) 读取 memory-index.md，获取当前任务和当前阶段：

- 当前任务：task-{id}
- 当前阶段：phase-{current}

b) 定位计划文件：

- auto-task/tasks/task-{id}/task-{id}-plan-phase-{current}.md

c) 提取关键内容：

- 产出物列表
- 验证标准列表
- 退出条件列表
- 预期内容描述

### 2. 检查产出物

对于每个计划产出物：

a) 检查文件是否存在

b) 如果存在：

- 检查文件内容是否非空
- 检查内容是否符合预期（基于计划描述）
- 输出：✅ {文件路径} 存在且内容有效

c) 如果不存在：

- 输出：❌ {文件路径} 缺失
- 记录到补充列表

d) 如果内容不符预期：

- 输出：⚠️ {文件路径} 内容与预期不符
- 记录到修复列表

### 3. 检查验证标准

对于每个验证标准：

a) 检查标准是否满足（基于实际情况）

b) 如果满足：

- 输出：✅ {标准描述}

c) 如果未满足：

- 输出：❌ {标准描述} - 未满足
- 记录原因和修复建议

### 4. 检查退出条件

对于每个退出条件：

a) 检查条件是否达成

b) 如果达成：

- 输出：✅ {条件描述}

c) 如果未达成：

- 输出：❌ {条件描述} - 未达成
- 记录到补充列表

### 5. 输出检查报告

```
========================================
阶段计划检查报告
========================================
阶段：Phase {current}
任务：{task-id}

产出物检查：
- ✅ {文件路径}
- ❌ {文件路径} - 缺失
- ⚠️ {文件路径} - 内容不符预期

验证标准检查：
- ✅ {标准描述}
- ❌ {标准描述} - 未满足

退出条件检查：
- ✅ {条件描述}
- ❌ {条件描述} - 未达成

========================================
```

### 6. 处理不一致情况

如果存在任何 ❌ 或 ⚠️：

a) 输出不一致项列表

b) 询问用户处理方式：

- "补充" → 执行补充逻辑
- "修复" → 执行修复逻辑
- "跳过" → 记录遗留问题
- "查看" → 输出详细信息后重新询问

c) 补充逻辑：

- 产出缺失 → 重新执行相应步骤
- 标准未满足 → 执行修复操作或标记风险
- 条件未达成 → 继续完善或标记遗留

d) 修复逻辑：

- 内容不符预期 → 修正产出文件
- 标准未满足 → 修正实现逻辑

e) 记录处理结果到阶段总结

### 7. 更新阶段计划文件

如果进行了补充或修复：

a) 更新 task-{id}-plan-phase-{current}.md：

- 更新验证标准状态
- 更新退出条件状态
- 记录补充/修复内容

b) 提交变更：

- git add auto-task/tasks/task-{id}/
- git commit -m "[task-{id}/phase-{current}] 阶段计划检查：补充/修复产出"

### 8. 输出最终结果

```
========================================
阶段计划检查完成
========================================
阶段：Phase {current}
状态：{全部一致 / 已补充修复 / 存在遗留问题}

处理结果：
- 补充产出：{数量}
- 修复问题：{数量}
- 遗留问题：{数量}

========================================
```

## 调用位置

在 `/at-plan-run` 最后（步骤11之后）调用：

- 步骤11：执行 /at-mem-fresh
- 步骤12：再次提交 memory-index.md
- **步骤13：执行 /at-plan-review**

## 关键原则

1. 严格检查：不遗漏任何产出物、标准、条件
2. 实际修复：缺失则补充，不符则修复
3. 用户决策：不一致时询问处理方式
4. 记录完整：所有检查结果和处理过程记录到阶段总结

## 错误处理

- 计划文件不存在 → 提示错误，退出
- 无法判断标准是否满足 → 标记为"待人工验证"
- 补充/修复失败 → 记录到遗留问题，不阻塞阶段完成
