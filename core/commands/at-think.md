## 用途

对任务进行全面、充分的思考，输出全面、详尽、切实可行的思考结果

## 参数

- $ARGUMENTS: 任务描述

示例：
/at-think 优化用户登录流程
/at-think 重构数据库层，提高性能
/at-think 新增支付功能，支持多种支付方式

## 流程

### Step 1: 分析任务描述

提取：

- 任务核心目标
- 关键要素
- 潜在约束

### Step 2: 结合实际情况思考

**多维度思考**（内部思考，不输出）：

1. **业务维度**
   - 任务的业务价值
   - 用户影响
   - 边界情况

2. **技术维度**
   - 现有架构是否支持
   - 需要的技术栈
   - 潜在技术风险

3. **实现维度**
   - 核心实现步骤
   - 关键技术选型
   - 验证方法

4. **资源维度**
   - 依赖关系
   - 所需工具
   - 开发环境

### Step 3: 输出全面的思考结果

**输出格式**：

```
## 思考结果

**目标**: {一句话目标}

**关键点**:
1. {关键点1}
2. {关键点2}
3. {关键点3}

**实现路径**: {实现路径}

**风险提示**: {主要风险}

**验证方法**: {如何验证完成}
```

## 注意事项

- **充分思考**: 内部思考要全面充分，但输出要简洁
- **实际导向**: 结合实际情况（代码库、环境、依赖等）
- **可执行**: 思考结果必须可执行、可验证
