---
description: 执行任务（支持单任务/多任务，支持全自动/半自动模式）
agent: build
---

模板文件位置：`.opencode/commands/auto-task/`

## 参数

```
/at-task-run [任务列表] [任务模式]

参数1 - 任务列表（可选）：
  - task-0,task-1,task-2  → 指定多个任务，按顺序执行
  - task-0                → 指定单个任务
  - all                   → 所有待执行任务
  - 省略                  → 所有待执行任务（默认 = all）

参数2 - 任务模式（可选）：
  - auto   → 全自动模式（阶段间、任务间无需用户确认）
  - half   → 半自动模式（阶段间、任务间需用户确认）
  - 省略   → 半自动模式（默认 = half）
```

## 执行流程

### 1. 参数解析与初始化

a) 解析任务列表参数：

- 如果提供了 task-0,task-1,task-2 → 任务队列 = [task-0, task-1, task-2]
- 如果提供了 task-0 → 任务队列 = [task-0]
- 如果提供了 all 或省略 → 读取 task-index.md，任务队列 = 所有待执行任务

b) 解析任务模式参数：

- 如果提供了 auto → 任务模式 = auto
- 如果提供了 half 或省略 → 任务模式 = half

c) 更新 memory-index.md：

```
### 状态
- 任务队列：task-0 → task-1 → task-2
- 任务模式：auto/half
```

d) 输出确认：

```
========================================
任务执行计划
========================================
任务队列：{task-0, task-1, task-2}
任务模式：{全自动/半自动}
========================================
```

### 2. 任务循环

初始化：任务计数器 = 0

循环：

a) 从任务队列取出第一个任务：

- 如果队列为空 → 输出"所有任务已完成"，退出循环
- 当前任务 = 队列第一个
- 更新 memory-index：当前任务 = {task-id}

b) 执行 /at-task-pop

- 确认任务状态为"待执行"
- 标记任务为"执行中"

c) 执行阶段循环：

初始化：阶段计数器 = 1

循环：

i) 执行 /at-mem-fresh - 刷新记忆索引

ii) 执行 /at-plan-refresh - 评估当前状态与下一阶段 gap - 优化下一阶段计划

iii) 执行 /at-plan-run - 严格按计划执行当前阶段 - 验证产出物 - 检查退出条件 - 生成阶段总结 - 提交代码

iv) 输出阶段执行结果：

       ```
       ========================================
       Phase {X} 完成
       ========================================
       任务：{task-id}
       产出：{产出文件列表}
       验证：{验证结果}
       ========================================
       ```

v) 检查是否存在下一阶段：- 读取任务目录，检查 plan-phase-{current+1}.md 是否存在

      如果存在：
      - 阶段计数器 += 1
      - 读取 memory-index "任务模式"

      如果是 half：
      - 输出"阶段已完成，请确认后继续"
      - 等待用户输入：
        - "继续" → 返回步骤 i) 执行下一阶段
        - "查看" → 输出 summary 内容，等待用户确认
        - "退出" → 退出命令
        - 其他指令 → 执行用户指令后继续等待

      如果是 auto：
      - 输出"自动进入 Phase {current+1}"
      - 返回步骤 i) 自动执行下一阶段

      如果不存在（已到达最后阶段）：
       - 输出"所有阶段已完成"
       - 执行 /at-task-review
         - 检查各阶段summary是否存在
         - 检查各阶段产出与plan一致性
         - 检查任务效果与预期一致性
         - 检查overall-plan退出条件
         - 不一致则改进或补充
       - 退出阶段循环

d) 任务完成处理：

执行 /at-task-finish

输出：

```
========================================
任务执行完成
========================================
任务ID：{task-id}
总阶段数：{阶段计数器}
完成时间：{当前时间}

所有产出物：
- {文件路径}
- {文件路径}

建议验证：
- 手动检查关键产出物
- 运行相关测试
- 确认满足预期
========================================
```

e) 检查任务队列是否还有下一任务：

- 从任务队列移除当前任务
- 读取 memory-index "任务模式"

如果是 half：

- 输出"任务已完成，请确认后继续下一个任务"
- 等待用户输入：
  - "继续" → 返回步骤 a) 执行下一任务
  - "退出" → 退出命令
  - 其他指令 → 执行用户指令后继续等待

如果是 auto：

- 如果队列不为空 → 输出"自动进入下一个任务"，返回步骤 a)
- 如果队列为空 → 输出"所有任务已完成"，退出循环

## 关键原则

1. 任务队列管理：
   - 任务列表参数解析后立即更新到 memory-index
   - 每完成一个任务从队列移除
   - 队列为空时自动退出

2. 模式检查点：
   - 阶段结束 → 检查 memory-index 任务模式 → 决定是否暂停
   - 任务结束 → 检查 memory-index 任务模式 → 决定是否暂停

3. 执行保证：
   - 严格按计划执行，不跳过任何步骤
   - 每个阶段执行完整验证和提交
   - 任意阶段失败停止执行并报告用户

4. 用户确认（半自动模式）：
   - 阶段完成时等待用户确认
   - 任务完成时等待用户确认
   - 支持"继续"、"查看"、"退出"指令

## 兼容性映射

```
原命令                           新命令
/at-task-run-all                → /at-task-run all auto
/at-task-run-all task-0,task-1  → /at-task-run task-0,task-1 auto
/at-task-run-half               → /at-task-run half
/at-task-run-half task-0        → /at-task-run task-0 half
/at-task-run-single             → /at-task-run auto
/at-task-run-single task-0      → /at-task-run task-0 auto
```

## 示例

```
/at-task-run
→ 执行所有待执行任务，半自动模式（阶段间需确认）

/at-task-run task-0
→ 执行 task-0，半自动模式

/at-task-run task-0 auto
→ 执行 task-0，全自动模式（无需确认）

/at-task-run task-0,task-1,task-2 auto
→ 执行 task-0→task-1→task-2，全自动模式

/at-task-run all auto
→ 执行所有待执行任务，全自动模式
```

## 错误处理

- 任务不存在 → 提示错误，列出可用任务
- 任务已在执行中 → 提示错误
- 阶段执行失败 → 停止执行，报告用户
- 用户输入"退出" → 保存当前状态，退出命令
